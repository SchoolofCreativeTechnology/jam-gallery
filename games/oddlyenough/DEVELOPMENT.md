# ODDLY ENOUGH — voice prototype handoff

6 November 2026. The current default is a Three.js pawnshop with the supplied shop, ten character models, ten item models, voice, bargaining, inventory and profit progression. The existing plain HTML/ES-module setup, private GitHub repository and intended jam-gallery hosting route are preserved. No package installation or build step is required. Maker context and devlog files are untouched.

## Current playable flow

1. Tap **Open the shop** once to enable character audio in the browser.
2. A buyer walks through the door, browses the shelves, picks up an object and approaches the counter. The next visit is a seller who enters carrying an object.
3. The camera moves to a side view: customer left, counter middle, shopkeeper right.
4. The customer speaks and their caption types into a cream conversation card. A matching cream bargain card beside it holds the item, current offers and receptiveness. The top HUD shows real cash, realized profit, level, visit count and the next unlock.
   Click the counter object to enlarge it, lift it into the air and rotate it slowly while continuing the conversation. Click the scene again or press Escape to return it. Keyboard users can focus the scene and press Enter or Space. Inspection resets when the visit ends.
5. Tap **Speak**, allow microphone access, speak, then tap **Send**. Recording continues until you tap Send or Cancel; there is no automatic speech timer. The transcript appears below the customer caption; the character responds in their stable, canonical personality. Spoken whole-dollar offers such as “I can sell it for eighty dollars” update the offer display. The small number field can correct a misheard amount.
6. A seller opens with an asking price and tries to sell high; a buyer tries to buy low. A proposed amount updates the offer display; when the NPC agrees, the trade waits for **deal** or **Confirm deal**. Accepting an existing customer quote with an explicit **deal** also completes it. Cash and the item move exactly once. After the spoken result, tap **Next customer**. Say **goodbye** to leave without a deal; **Next customer** also works as a voice command. **Undo last purchase/sale** reverses only the latest saved transaction and starts a fresh visit, preserving earlier progress.

The scale is a moving marker between **Resistant** and **Convinced**, using the actual receptiveness value that controls negotiation. Relevant evidence and reasonable prices move it right. Every difficulty gives one playful unsupported pitch the benefit of the doubt; further bluffs, condition denial, insults and extreme offers move it left. Personality determines the response strength. Repeated arguments or tiny price increments cannot build unlimited receptiveness.

Ten named character definitions use eight personality profiles that change manner, motivation and voice. Their model, name, backstory and default personality remain consistent across visits. The customer stays in their buyer/seller role and uses canonical object facts. All ten character files are byte-identical to the supplied `Pawn Shop Pack/3d/characters` models, animated through separate runtime transforms. The full supplied shop and low-poly models replace the graybox; primitives remain only as a bounded loading-failure fallback; the shopkeeper now uses the exact supplied subway-guy model.

The live entry point now features Mr. Marlowe, the fish man, as an easy first buyer whenever stock is available. His formal analytical voice remains consistent. The controller still supports `firstRole` for tests and other entry points. Buyers choose only owned stock; sellers bring an unlocked object the shop does not own. Visits normally alternate, with inventory availability taking precedence. Trade progress is saved locally after each deal; a reload restores the ledger and starts a fresh visit.

## Voice and API boundaries

`server.mjs` provides static files plus same-origin `/api/interpret`, `/api/talk`, `/api/transcribe` and `/api/speak`. The supplied gateway key is injected into the server process environment only. It never goes to the browser, source control or logs.

- Dialogue: `claude-code/vmc/jam-cheap[1m]`, canonical character/object context and bounded conversation history. The model returns only a validated short line, expression and language observations. It receives the exact public offers and engine result, but cannot choose prices, transfer objects or spend money. Canonical price/result sentences keep spoken and displayed offers aligned. Character-specific provenance is included only when its item ID matches the current object. Preferred objects guide visits when available; the Visitor appears only when the shop owns the alien egg and never selects unrelated stock.
- Offer interpretation: the same gateway model classifies the latest utterance using buyer/seller role, conversation and current quotes. It must return an intent, exact supporting text and a grounded amount. Complaints, echoes, hypothetical prices and questions are not proposals. Offers require confidence at least 0.8 and a clause-level evidence check; acceptance requires 0.9. A failed live interpretation requests clarification instead of executing a regex-derived amount. A bare number remains ambiguous without sufficient context. Natural proposals such as “yeah, so I am offering 50 for it,” “can we do fifty?” and “fifty sounds fair” are supported; no exact command phrase is required. The explicit numeric Offer control remains available. Only a confirmed agreement can mutate the ledger.
- Transcription: Vercel AI Gateway `openai/whisper-1`. Browser MediaRecorder sends a bounded recording after the player explicitly taps Speak and then Send. Tracks are released promptly. No recordings are stored by this application. Native browser SpeechRecognition is a compatibility fallback where available.
- Character speech: Vercel AI Gateway `openai/tts-1`, with a fixed voice selected by canonical personality. MP3 is decoded and played through a user-unlocked AudioContext. Browser speech synthesis is a fallback. Voice and caption completion serialize the next conversational turn.

Host/origin checks, bounded payloads, provider schema validation, deadlines and concurrency controls protect these routes. There is no application-imposed lifetime or per-minute speech/dialogue quota. Two concurrent provider calls, request deadlines, 24 MiB audio payload validation and a 12,000-character utterance bound keep requests reliable; provider-side limits still apply. Audio recording requests 32 kbps compression. Oversized speech produces an explicit error rather than silently truncating or submitting a partial offer. A spoken turn normally uses transcription, interpretation, dialogue and speech calls. Invalid requests and provider details never expose the key. Authored lines preserve the loop if live dialogue fails.

Microphone access requires browser permission and localhost or HTTPS. A browser or desktop wrapper can deny capture independently of the transcription server. If the embedded preview denies access, open the same localhost URL in Chrome and allow the site's microphone; check macOS microphone access for that browser if necessary. The game does not record on page load or on Enter shop. The default recorder path sends audio after Send; cancelling before submission discards it. Native recognition uses the browser's speech service while listening. Audio is not persisted by the application.

Static hosting still works with authored dialogue and browser-supported speech features. Live server routes are local development functionality; they have not been deployed to the gallery. A production backend can later expose the same contract without changing the visual scene.

## Run and verify

- Local live server: inject `AI_GATEWAY_API_KEY` into the process environment, then `node server.mjs` (or `npm start`). Default port 8001. With no key, authored dialogue remains usable. Never put a key in frontend code or a served file.
- Original static server: macOS `python3 -m http.server 8000 --bind 127.0.0.1`; Windows `py -m http.server 8000 --bind 127.0.0.1` (or `python`). Static hosting cannot expose the local AI routes.
- Tests: `node --test tests/*.test.mjs` or `npm test`. HTTP tests need loopback socket access. Automated tests use provider stubs and never spend model credits.

Earlier live checks passed using fictional test audio: a 3.44-second question transcribed in 1.51 seconds; the transcript produced a relevant seller reply in 2.65 seconds; NPC speech returned a valid 5.208-second MP3 in 1.35 seconds. These are individual local observations, not latency guarantees. Browser checks cover buyer/seller staging, side-view composition, typed captions, microphone transcript display and spoken-reply status. The user confirmed speech input is working. Live browser trading also completed a $73 purchase (cash $120 → $47), then a $52 sale of a $48-cost item (cash $47 → $99; realized profit $4). The item floated and rotated during negotiation, then reset on departure. Actual audio quality and hardware microphone behavior still depend on the player's browser and device permissions.

Regression tests cover conversation cancellation, serialized presentation, recording cleanup, stale callbacks, deadlines, server limits and strict schemas, plus the retained ledger/save/negotiation engine. The reported $107 complaint was also checked through the live model and game controller: it left the player offer empty and cash unchanged. The subsequent spoken correction identified an $80 proposal without executing a trade. Tests cover false AI positives, pending-price corrections, explicit confirmation, duplicate protection, marker direction and undo replay. Earlier automated economy checks completed 80 trades over ten days. No human playtest or balance assessment is claimed.

## Visual teammate integration

`main.js` assembles `Prototype`, `createScene`, `createMicrophone`, `createSpeechPlayer` and the responsive HUD and conversation cards. `blockout.js` implements `startVisit({customer,item,role})`, `endVisit()`, `cancelVisit()`, `setReaction(expression,status)`, `render()`, `resize()` and `renderer.setAnimationLoop`. Visit promises resolve only after walking/camera choreography; cancellation resolves obsolete visits safely. Preserve this adapter while updating models, lights and animations. `scene-assets.js` caches GLB templates, gives each visit independent transforms, and bounds unavailable-asset loading. Arrival waits for the correct assets, and cancelled loading cannot resurrect an old visit. Legacy catalog IDs, costs and evidence IDs remain stable for saved ledgers.

`prototype.js` owns visits, spoken offers and atomic settlement. `bargaining.js` parses whole-dollar offers and owns difficulty, receptiveness, acceptance thresholds and counteroffers. `progress.js` stores replayable transactions and derives profit, levels and stock unlocks; invalid or inconsistent saves are rejected. Easygoing negotiators accept a wider range of prices, while tough negotiators need stronger evidence. Relevant facts and honest condition concerns improve receptiveness once; repeated pitches cannot farm concessions, and repeated bluffs or extreme offers hurt trust. Every profile, including tough negotiators, gets one bounded benefit-of-the-doubt concession for a playful pitch; this never changes item facts or automatically settles a trade. Questions do not earn evidence credit. Latest offers remain available while the player talks.

The shop starts with $120 and three low-value items with explicit acquisition costs. Profit is realized only when an item sells: sale price minus its acquisition cost. Purchases reduce cash and add stock but do not award profit. At $75 realized profit a fifth catalog item unlocks; at $200 the sixth unlocks. Further profit advances levels and unlocks the rest of the ten-item catalog. The UI distinguishes the player’s asking price from the customer’s offer when selling, and the player’s offer from the seller’s asking price when buying. Amounts must be whole dollars from $1 to $500; ambiguous speech asks for one exact amount instead of silently choosing.

`prototype.js` also owns conversational cancellation. `presentReply({line,customer,signal})` waits for audio/captions; cancellation prevents old responses entering a new encounter. `prototype-ui.js` owns caption animation only. `microphone.js` owns capture/transcription; `speech-player.js` owns playback. Backend modules never get imported by the browser.

## Front-end assets and reference

The supplied Pawn Shop Pack contributes the furnished store, all ten characters and ten distinct items as local GLB files. Asset credits and local font licenses are recorded in `meta.json`; Blender sources and unused exports are not shipped. The UI is adapted from the Game Jam Figma workflow and screenshots, using Archivo Black, IBM Plex Mono and VT323 bundled locally. It retains the live 3D scene rather than using a screenshot as a backdrop. The Figma's future memory, day-clock and black-market ideas are not presented as implemented mechanics.

The side camera keeps the customer left, counter middle and shopkeeper right. Buyers still browse and collect stock; sellers carry their object in. Counter inspection enlarges the real object model, floats it and rotates it slowly. Character speech keeps the same canonical voice mapping, and microphone capture, typewriter completion, price interpretation, confirmation and ledger persistence use the existing adapters.

The shopkeeper uses `01-subway-guy.glb`; that same character is excluded from visiting customers. All ten item GLBs were hash-checked against the exact supplied `3d/items` files. Added a faceted plant, worn seating, bin, papers, cartons, painted signs, vents and ductwork without obstructing customer paths. The shelves now render authoritative inventory, one physical copy per owned object. A buyer's selected object is hidden in its shelf slot while it is in hand or on the counter; a completed purchase occupies its stable shelf slot after the visit, and a completed sale removes it. Decorative counter curios are six distinct generated miniatures, separate from tradable catalog objects. Visit selection prefers unseen eligible items and avoids immediate repeats; just-sold objects have a two-visit cooldown. The finite catalog can cycle after alternatives are exhausted, preserving a playable loop. Existing stock and transaction saves are preserved. The cream bargaining card matches the dialogue card, while textured wood, worn teal shelving and warmer lighting enrich the supplied low-poly environment.
